## Моя рефлексия
Во второй работе модель вызывается из Python через API, поэтому программа может автоматически обработать все пятнадцать заявок, а не отправлять их по одной в обычном чате.
В цепочке LangChain промпт задаёт задачу, модель формирует ответ, а парсер преобразует и проверяет полученные данные.
Системное сообщение содержит правила извлечения, а пользовательское сообщение — только текст текущей заявки без эталонного ответа.
На варианте 18 базовая техника правильно определила количество людей в пятнадцати случаях из пятнадцати, что соответствует точности 100 процентов.
Для расширенного решения выбрана техника few-shot с примерами, не входящими в проверочный вариант, и структурированный JSON-ответ с проверкой через Pydantic.
JSON позволяет отдельно использовать число взрослых и детей, дату заезда, длительность, суточную цену и пожелания, а ручная разметка задаёт эталоны для проверки этих полей.
У расширенной техники четыре ответа не прошли валидацию, а точность общего количества составила 73,3 процента, то есть усложнение задачи ухудшило этот показатель.
Точность числа взрослых и детей составила по 73,3 процента, даты и количества ночей — по 53,3 процента, цены — 66,7 процента, а средняя по пяти дополнительным полям — 64 процента.
Например, в заявке «с 20–22 на 10 дней» отсутствует месяц, поэтому эталонная дата равна null, но при диагностическом повторе модель вернула недопустимую дату --20-22.
Другой пример ошибки — цена 10000 вместо 2000 рублей в заявке с двумя взрослыми и двумя детьми, поэтому корректный формат JSON сам по себе не гарантирует правильного смысла ответа.
Наиболее устойчивым результатом оказалась базовая оценка количества людей, а следующим улучшением стали бы более строгая проверка дат по исходному тексту и отдельные правила расчёта длительности с повторным замером без подмены результатов.
